# lib-js

JavaScript interop surface — `JS` grade, typed call/invoke/await
arrows for codegen-generated adapters. Two modules: `js` (the contract
ops) and `js/worker` (Web Worker bindings).

## Layout

| path | role |
| --- | --- |
| `src/index.hnl` | the `js` module — `call`, `invoke`, `construct`, `on`/`off`, `error`, `await` |
| `src/worker/index.hnl` | Web Worker bindings — `spawn`/`post_message`/`on_message`/`self_close`; intentionally NOT in `pkg.hnl` `modules` (see manifest comment — N-module layout would relocate `js` and break path deps); import as `from "js/worker" import …` |
| `specs/dom.idl`, `specs/html.idl` | committed WebIDL specs (w3c/webref pinned) |
| `handl-packages/generated/` | gitignored DOM/HTML bindings — regenerated by the gate |
| `pkg.hnl`, `scripts/hnl-gate.sh` | manifest (dep `type`) + regen+gate script |
| `workflows/gate.yaml` | CI — shared `handl-gates` campaign |

## Contract

- `js/worker` stays out of `pkg.hnl` `modules` deliberately — do not
  "fix" it without migrating `js` itself to the N-module layout.
- Codegen also emits raw Worker bindings
  (`generated/html*/Worker*`, `DedicatedWorkerGlobalScope*`, …) with a
  different API shape; `js/worker` remains the ergonomic surface.
- Never commit `handl-packages/generated/`.

## Verification

```bash
HNL=../host-cli/target/debug/hnl scripts/hnl-gate.sh
```
